How the comparison works

Baseline costs, move strings, and starting thumbs are copied from the source sheet. Each revision records the cheapest execution of that same algorithm and starting thumb using the model's regrip limit. Deltas beside the baseline are incremental, relative to the previous saved revision. The current column shows the selected revision's total. Each case collapses independently. Algorithms are sorted by current cost within their case; equal costs keep source-row order. Position change compares each entry with its baseline position in that same case. Filters do not renumber positions. Unavailable executions appear last and remain unranked. Live app evaluates the current code in your browser; save a named snapshot to retain a change permanently.

The sheet does not include original finger-by-finger paths. Popups show the selected saved or live execution, with its actual move, regrip, repeated-finger, and orientation costs. Missing executions stay unavailable and are never treated as zero.

To save a change, run node scripts/snapshot-costs.mjs --id change-name --label "What changed" from the repository root. Commit the resulting history with the rule change. Baseline JSON is never rewritten by this command.
